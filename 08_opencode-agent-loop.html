08. Agent loop в OpenCode: когда агент останавливается и что управляет циклом

Агент — это, в сущности, while: модель вызывает инструменты, результаты возвращаются в контекст, модель вызывается снова. Но у любого while должен быть выход — и три вопроса этой заметки (они же три вопроса владельца, замкнувшие цикл доклада): (1) когда OpenCode останавливается — каковы критерии; (2) что раздувает и сжимает цикл — промпт, скиллы, модификации агента; (3) чем это отличается от других harness. Есть и красивая параллель с заметкой 01: там генерация — цикл по одному токену, здесь harness — цикл по целому шагу.

Достоверность помечена по всему тексту: доки — официальный источник, код, не доки — исходники OpenCode, вывод — реконструкция из косвенных фактов, пересказ — пересказ чужой документации. Главный пробел честно: явного единого критерия остановки в доках V2 нет — раздел «Вопрос 1» собран из косвенных формулировок и кода.

Мини-глоссарий

agent loop
цикл «модельный вызов → tool-вызовы → результат → следующий модельный вызов».
шаг (step)
одна итерация цикла: модельный вызов с его tool-вызовами.
tool-driven continuation
продолжение модельных вызовов, пока их продолжают tool-вызовы.
steps
максимум модельных шагов агента; на последнем шаге инструменты отнимаются, модель просит подытожить текстом.
plain rejection vs rejection with feedback
«голое» отклонение инструмента vs отклонение с причиной, которую видит модель.
компакция (compaction)
замена старой части разговора саммари, чтобы сессия жила за пределами контекста модели.
circuit breaker
автоматический прерыватель хода (у Codex: после серии отказов).

1. Канон: Reason → Act → Observe

Каноническая рамка — ReAct: чередование рассуждений и действий, цикл Reason → Act → Observe (ReAct: Synergizing Reasoning and Acting in Language Models). Anthropic формулирует короче: агенты — это «LLMs using tools based on environmental feedback in a loop», и в цикл «common to include stopping conditions (such as a maximum number of iterations)» (Anthropic: building effective agents).

Вся заметка — о том, как эти stopping conditions устроены у OpenCode и его соседей.

2. Петля в OpenCode V2

Формальное описание петли в доках косвенное: хук context «runs for the agent loop, including tool-driven continuations» (server plugin docs) — модельные вызовы продолжаются, пока их продолжают tool-вызовы доки, косвенно. Завершение сессии — событие session.idle («Session completed»), а эндпоинт POST /api/session/{sessionID}/prompt описан как «schedule agent-loop execution» (API reference; migrate-v1) доки.

И заглянув под капот V1-раннера код, не доки, ветка v1: там цикл — буквально while(true) с break «exiting loop» и комментарием «Some providers return "stop" even when the assistant message contains tool calls. Keep the loop running…» (prompt.ts).

Старт цикла — POST /api/session/{sessionID}/prompt («schedule agent-loop execution») доки; условие продолжения — tool-вызовы модельного ответа доки, косвенно.

3. Вопрос 1: критерии остановки

Прямой формулы «сессия завершается, когда X» в доках нет. Реконструкция даёт четыре механизма вывод:

#МеханизмЧто происходитДостоверность
амодель перестала звать инструментыответ без tool-вызовов → событие session.idleдоки, косвенно
бисчерпан stepsинструменты отнимаются, модель принуждена подытожить текстом; новый ввод пользователя сбрасывает счётчикдоки
вplain rejection«ends the current step» — конец текущего шагадоки, дословно
гтерминальная ошибка моделипосле политики retry — циклу нечем продолжатьсядоки + вывод

steps — лимит с мягким финалом доки

Agents docs: steps — «positive maximum number of model steps»; «On the final step, OpenCode removes tools and asks the model to summarize in text. New user input resets the allowance». Схема конфига (config.json) говорит то же: «Maximum number of agentic iterations before forcing text-only response»; maxSteps и experimental.continue_loop_on_deny помечены deprecated. Важно: исчерпание — не ошибка, а принудительный текстовый финал. Механика последнего шага видна в коде код, не доки: инструменты не материализуются, ставится toolChoice: "none", модели уходит промпт «MAXIMUM STEPS REACHED… Tools are disabled until next user input. Respond with text only» (issue #45328; max-steps.ts). Дефолт steps в доках не указан — не будем его выдумывать.

Deny — два разных исхода доки

Дословно из server plugin docs, Permissions: «A deny rule or a rejection with feedback rejects with a Tool.Error that carries the reason, so the model sees it and continues. A plain rejection ends the current step». То есть deny-правило и отклонение с фидбеком цикл не рвут — модель видит причину и продолжает; «голое» отклонение кончает текущий шаг. Что «конец шага» значит для цикла в целом, в доках не раскрыто — оставляем дословную формулировку с этой оговоркой.

Родственные факты: явный настроенный deny финален и хук evaluate не вызывается (формулировка «does not invoke the hook» — тоже из server plugin docs; общий контекст прав — permissions docs; механика — в заметке 05); а V1-флаг continue_loop_on_deny в V2 «accepted but unsupported» — игнорируется с warning (migrate-v1; переименования — в заметке 02).

Компакция — не остановка доки

Compaction docs: компакция — «replacing older conversation with a summary, so the session can keep going past the model's context limit» — цикл продолжается. Авто-компакция «pauses the session» — пауза, не завершение; experimental.background_compaction (default false, знакомый по заметке 03 зонтик experimental.*) — «the session keeps going; the summary is held». Переполнение контекста: дословная формула из compaction docs (Limits → Recovery) — «compacted and retried once. A second rejection is returned as an error».

Retry — политика, не критерий доки

Retry-хук (тема заметки 05) касается только сбоев провайдера («Override the retry decision for a provider failure»), может сделать ошибку повторяемой или наложить вето, но «built-in maximum attempt count remains a hard limit». Это регулирование повторов внутри витка, а не условие выхода из цикла.

4. Вопрос 2: что управляет размером и числом циклов

РычагЭффект на циклДостоверность
AGENTS.md / инструкцииглобальный файл + все от рабочей директории вверх грузятся сразу, вложенные — лениво по ходу (instructions docs); изменения инжектируются «before the next model request», «at the next step boundary without queuing a message turn» — не добавляют модельный виток; CLAUDE.md не используетсядоки
Скиллына каждом шаге — лёгкий листинг «only the ID, name, and description, not the full Markdown body»; тело догружается инструментом skill («Adds the Markdown body… to the conversation») (skills docs). Загрузка тела = +1 виток цикла и постоянное место в контексте вывод; качество description определяет выбор и число ложных витковдоки + вывод
Поля агентаsystem prompt + model + permissions + steps (agents docs; поля — в заметке 04): промпт и права решают, как часто модель зовёт инструменты; steps — жёсткий потолокдоки
Субагенты«Subagents run with fresh context in foreground or background child sessions» (agents docs) — собственный цикл с чистым контекстом; experimental.subagent_depth — «Defaults to 1, so a subagent cannot start another subagent» (config docs)доки
Code Modeexecute — «parallel independent calls and for processing results without adding every intermediate value to the model context» (tools docs) — меньше витков и меньше контекста на виток (разбор — в заметке 07)доки

Куда всё это попадает: порядок сборки промпта доки — system → Code Mode guidance → MCP/skill guidance → AGENTS.md + instructions → дата/окружение → session entries (instructions).

Свести в «регуляторы» вывод (в доках в таком виде не сформулированы): steps — жёсткий потолок; инструкции и описания — меньше ложных витков; Code Mode — схлопывает лестницу вызовов; субагенты — выносят цикл из родительского контекста.

Исторический штрих: ещё в сетапе владельца v1 (Установка openCode & OMO) короткий промпт осознавался как «получается диалог… задача выполняется в несколько итераций» — agent loop был всегда, V2 лишь сделала его настраиваемым.

Интерактив 2

«Рычаги цикла» — одна задача, пять конфигураций

Демо-задача: разберись в 5 файлах (auth.ts, config.ts, agent.ts, tools.ts, prompt.ts) и дай сводку. Переключайте конфигурации — прогон повторяется, а мини-график внизу сравнивает все пять по осям «витки × контекст». Оранжевые чипы — промежуточные значения, оседающие в контексте; зелёные — только итог.

0витков (родитель) 0чипов в контексте
витки цикла

промежуточные значениятолько итог
мини-график: витки × контекст — все пять конфигураций
база: 6 витков / 7 + AGENTS.md: 6 / 8 + скилл: 7 / 9 + субагент: 2 / 3 (родитель) + Code Mode: 1 / 2

Условные единицы контекста — число чипов (задача, инструкции, тела скиллов, промежуточные результаты, итог). У субагента показан контекст родителя: витки child-сессии в него не попадают. Формулировки — из заметки с маркировкой достоверности.

5. Вопрос 3: три harness

МеханизмOpenCode V2Claude CodeCodex
Формула цикла модельные вызовы, продолжаемые tool-вызовами; финал — session.idle доки, косвенно «Receive prompt → Evaluate and respond → Execute tools → Repeat… until it produces a response with no tool calls → Return result»; полный цикл = turn CC-доки работает в цикле: вызывает модель и выполняет действия по её выходу; завершение — выполнение задачи или отмена пользователем пересказ Codex-док (Codex manual)

«Не дай остановиться» аналога Stop-хука в session-хуках нет — только событие session.idle вывод-оговорка Stop-хук: decision: "block" «prevents Claude from stopping» + reason; защита — stop_hook_active и «8-consecutive-continuation cap» со сбросом при любом tool-вызове CC-доки версионно-текучее — на октябрь 2026 —
Границы вместо лимита permissions/deny как границы шага доки read-only параллелятся, мутирующие — последовательно CC-доки sandbox (read-only / workspace-write / danger-full-access) × approval policy (untrusted / on-request / never / granular); circuit breaker — «In the current open-source implementation» — прерывание хода после 3 подряд denials или 10 за последние 50 reviews Codex-доки
Хуки по каденциям session-уровень (prompt, context, …), per-tool, retry доки per session (SessionStart/End), per turn (UserPromptSubmit, Stop, StopFailure), per tool call (PreToolUse/PostToolUse) CC-доки авто-ревью как встроенный перехватчик Codex-доки

Источники колонок: Claude Code — agent loop и hooks; Codex — Codex manual и разделы agent-approvals-security / sandboxing-auto-review.

Философии остановки вывод: OpenCode — лимит с мягким финалом (summarize); Claude Code — лимит с ошибкой плюс уникальный режим «не дай остановиться» (Stop-хук с предохранителем); Codex — сознательный отказ от лимита в пользу sandbox × approval + circuit breaker. Прямая аналогия «Stop-хук ↔ approval policy» некорректна: общее только то, что остановка — управляемое событие.

Контекст для Code Mode: Cloudflare формулирует аргумент так — «the output of each tool call must feed into the LLM's neural network, just to be copied over to the inputs of the next call… When the LLM can write code, it can skip all that» (Cloudflare code mode; developers.cloudflare.com) — конкретных цифр кратности в первоисточниках нет, не приписываем.
