# 05. Команды и хуки в OpenCode V2: горячие фразы и перехватчики жизненного цикла

У V2 две главные точки расширения для того, кто хочет не просто пользоваться агентом, а обучить его своим ритмам работы. **Команды** — «горячие фразы»: повторяемый промпт один раз сохраняется в markdown и дальше вызывается по имени. **Хуки** — «перехватчики»: ваш код встраивается в этапы жизни сессии, инструментов, прав и shell-процессов. Точки связаны: команда может исполняться агентом или уйти в фоновую child-сессию ([тема заметки 04](04_opencode-multiagent.md)), а хуки живут в плагинах — там, где [заметка 02](02_opencode-v1-vs-v2.md) обещала «новый plugin API» (breaking change №1, наконец раскрываемый). Источники — [V2 commands docs](https://opencode.ai/v2/docs/commands) и [server plugin docs](https://opencode.ai/v2/docs/build/plugins/server).

## Мини-глоссарий

- **custom-команда** — markdown-шаблон промпта, вызываемый слэшем: `.opencode/commands/<name>.md` → `/name`.
- **frontmatter** — YAML-шапка markdown-файла с полями конфигурации; тело файла — сам шаблон.
- **shell-блок** — конструкция вида `` !`git diff` `` в теле команды: вывод shell-команды вставляется в промпт до отправки модели.
- **плагин** — npm-пакет расширения; хуки живут именно в нём.
- **домен хука** — типизированная группа перехватчиков: `ctx.tool`, `ctx.session`, `ctx.permission`, `ctx.shell`.
- **адмиссия промпта** — момент приёма промпта в сессию; хук `prompt` может его отредактировать.

## Команды: markdown → `/name`

Идея та же, что у агентов в 04: расширение — это файл в вашем репозитории, а не строка в конфиге. Файл `.opencode/commands/<name>.md` превращается в команду `/name`: frontmatter — поля, тело — шаблон промпта. (Из переименований заметки 02: раздел `command`→`commands`, `subtask`→`subagent` — легаси-имя принимается.)

### Где живут команды

| Источник | Локация | Имя команды |
|---|---|---|
| Проектные | `.opencode/commands/<name>.md` | `/name` |
| Глобальные | `~/.config/opencode/commands/` | `/name` |
| Вложенные пути | подкаталоги | вложенные имена (`/team/review`) |

### Поля frontmatter

| Поле | Роль |
|---|---|
| `description` | описание команды |
| `agent` | каким агентом исполняется |
| `model` | модель для этой команды |
| `subagent` | `true` — исполнение в фоновой child-сессии (ниже) |

### Аргументы: одна строка против позиционных

Шаблон может подставлять аргументы двумя способами: `$ARGUMENTS` — вся строка аргументов целиком; `$1`, `$2`, … — позиционные, где кавычки группируют слова в один аргумент. На вызове `/review fix auth bug` строка `$ARGUMENTS` станет «fix auth bug», а на `/review "fix auth" bug` подстановка `$1` получит «fix auth», `$2` — «bug». Плюс fallback: аргументы не теряются — дописываются в body после пустой строки.

### Shell-блоки: данные до модели

Конструкция `` !`git diff` `` исполняет shell-команду и вставляет её вывод в промпт **до** отправки модели — удобно подложить контекст (диф, статус, список файлов), не копируя его руками.

> ⚠️ Warning из доков: shell-блоки выполняются **вне permission-потока** — разрешения не спрашиваются. Вставлять только доверенные команды; вся защита permissions из заметок 02 и 04 на этот механизм не распространяется.

### `subagent: true`: команда в фоне

С этим флагом команда исполняется в фоновой child-сессии, а результат возвращается родителю — прямая параллель с субагентами из заметки 04: родитель заказал работу, исполнитель отчитался.

### Приоритеты: источники и модель

- **Источники команд:** проектные перекрывают глобальные, ближние перекрывают дальние — та же логика «ближний сильнее», что у слоёв конфигурации из [заметки 03](03_opencode-architecture-config.md).
- **Модель:** команда → агент → сессия. Самое специфичное побеждает: явный `model` в frontmatter перекрывает модель агента, а та — модель сессии.
- **Hot-reload:** сохранение файла обновляет команду без рестарта — механика из заметки 03 распространяется и на команды.

## Хуки: перехватчики жизненного цикла

### Хуки живут в плагинах

В V2 хук невозможно описать строкой конфига — он живёт в **плагине**. Плагин — это один npm-пакет ([plugins overview](https://opencode.ai/v2/docs/build/plugins)), до четырёх частей: **Server** (инструменты, хуки, интеграции, команды, агенты), **TUI**, **GUI** (desktop) и **RPC** (типизированный контракт). SDK — один пакет `@opencode/plugin`; плагины автозагружаются из `.opencode/plugins/`. Заметьте: Server-часть плагина может привозить не только хуки, но и команды, и агентов.

### Домены хуков

Регистрация — на типизированных доменах, не строками. Путь промпта через систему с точками перехвата:

```text
   промпт пользователя
        |
        v   ctx.session.hook: prompt
   адмиссия промпта (можно отредактировать)
        |
        v   ctx.session.hook: context / generate / ...
   МОДЕЛЬНЫЙ ВЫЗОВ (сессия) <-------------------+
        |                                       |
        v   ctx.permission.hook: evaluate       |
   разрешения: пересмотр allow/ask              |
        |         (явный deny финален)          |
        |                                       |
        v   ctx.tool.hook: execute.before       |
   ИНСТРУМЕНТ (input можно инспектировать       |
        |         или подменить)                |
        |   если это shell-инструмент:          |
        |      ctx.shell.hook: create.before    |
        |      (команда/cwd/timeout/shell/env)  |
        |      -> запуск shell-команды          |
        v   ctx.tool.hook: execute.after        |  петля возврата:
   результат / ошибка --------------------------+  результат -> модель,
                                                   следующий виток цикла;
                                                   (на каждом витке - context-хук)
```

Полная карта доменов и сценариев:

| Домен | Хук | Что перехватывает / типичный сценарий |
|---|---|---|
| `ctx.tool` | `execute.before` | input инструмента до выполнения — инспекция или подмена |
| | `execute.after` | результат или ошибка — аудит, постобработка |
| `ctx.session` | `prompt` | редакция промпта при адмиссии |
| | `context` / `compaction` / `generate` / `title` | разные типы модельных вызовов: system / tools / options |
| | `model.request` | заголовки запроса к модели |
| | `http.request` / `http.response` | нативный HTTP |
| | `experimental.ws.handshake` / `send` / `receive` | экспериментальные websocket-хуки |
| | `retry` | политика повторов |
| `ctx.permission` | `evaluate` | пересмотр allow/ask после применения правил; явный deny финален |
| `ctx.shell` | `create.before` | правка команды, cwd, timeout, shell (исполняемого), env перед запуском |

### Правила выполнения

- несколько плагинов на одном хуке выполняются **в порядке регистрации**;
- изменения, сделанные хуком, касаются **только текущего вызова** — ничего постоянного.

### Наследие V1

Пара `tool.execute.before` / `tool.execute.after` из V1 не исчезла — стала парой `execute.before` / `execute.after` на домене `ctx.tool`. V1-имена встречаются только внутри V1-совместимого `server()`-экспорта (тот самый dual-support из заметки 02, позволяющий одному пакету работать в обоих мирах).

## Две философии: OpenCode V2 vs Claude Code

Аудитория доклада знает Claude Code — там тоже есть хуки, но философия другая ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)):

| | Claude Code | OpenCode V2 |
|---|---|---|
| Что такое хук | событие жизненного цикла: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `PermissionRequest`, … | TypeScript-API на типизированных доменах внутри плагина |
| Как настраивается | классически — shell-команда в JSON-настройках; сейчас есть и другие типы обработчиков (HTTP-эндпоинты, MCP-вызовы, LLM-промпты, субагенты) | код плагина (npm-пакет, SDK `@opencode/plugin`) |
| Философия | декларативный shell-обход: «на событие X запусти команду Y» | программный API: типы, домены, композиция логики |

Практическая разница: shell-команда легко пишется и так же легко разрастается в скрипты-«костыли»; плагин требует npm-окружения, зато даёт типизированный контракт и естественную эволюцию до инструментов и агентов.

## Команды и хуки одним взглядом

| Вопрос | Ответ |
|---|---|
| Что такое команда | markdown-шаблон промпта: `.opencode/commands/<name>.md` → `/name` |
| Frontmatter команды | `description`, `agent`, `model`, `subagent` |
| Аргументы | `$ARGUMENTS` — вся строка; `$1`/`$2`… — позиционные (кавычки группируют); fallback — дописывание после пустой строки |
| Shell-блок | `` !`cmd` `` — вывод в промпт до модели; ⚠️ вне permission-потока |
| Фоновое исполнение | `subagent: true` — child-сессия, результат возвращается родителю |
| Приоритет модели | команда → агент → сессия |
| Приоритет источников | проектные > глобальные, ближние > дальние; hot-reload без рестарта |
| Где живут хуки | в плагинах (Server-часть npm-пакета), автозагрузка из `.opencode/plugins/` |
| Домены | `ctx.tool` / `ctx.session` / `ctx.permission` / `ctx.shell` |
| Порядок и область | хуки нескольких плагинов — по порядку регистрации; изменения — только текущий вызов |
| Наследие V1 | `tool.execute.before/after` → `execute.before/after`; V1-имена только в `server()`-экспорте |
| vs Claude Code | события + shell-команды в настройках ↔ типизированный TypeScript-API в плагине |
