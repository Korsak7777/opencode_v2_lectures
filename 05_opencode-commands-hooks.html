05. Команды и хуки в OpenCode V2: горячие фразы и перехватчики жизненного цикла

У V2 две главные точки расширения для того, кто хочет не просто пользоваться агентом, а обучить его своим ритмам работы. Команды — «горячие фразы»: повторяемый промпт один раз сохраняется в markdown и дальше вызывается по имени. Хуки — «перехватчики»: ваш код встраивается в этапы жизни сессии, инструментов, прав и shell-процессов. Точки связаны: команда может исполняться агентом или уйти в фоновую child-сессию (тема заметки 04), а хуки живут в плагинах — там, где заметка 02 обещала «новый plugin API» (breaking change №1, наконец раскрываемый). Источники — V2 commands docs и server plugin docs.

· Мини-глоссарий

custom-команда
markdown-шаблон промпта, вызываемый слэшем: .opencode/commands/<name>.md → /name.
frontmatter
YAML-шапка markdown-файла с полями конфигурации; тело файла — сам шаблон.
shell-блок
конструкция вида !`git diff` в теле команды: вывод shell-команды вставляется в промпт до отправки модели.
плагин
npm-пакет расширения; хуки живут именно в нём.
домен хука
типизированная группа перехватчиков: ctx.tool, ctx.session, ctx.permission, ctx.shell.
адмиссия промпта
момент приёма промпта в сессию; хук prompt может его отредактировать.

· Команды: markdown → /name

Идея та же, что у агентов в заметке 04: расширение — это файл в вашем репозитории, а не строка в конфиге. Файл .opencode/commands/<name>.md превращается в команду /name: frontmatter — поля, тело — шаблон промпта. (Из переименований заметки 02: раздел command→commands, subtask→subagent — легаси-имя принимается.)

.opencode/commands/<name>.md  →  /namefrontmatter — поля конфигурации · тело файла — шаблон промпта

Аргументы: одна строка против позиционных

Шаблон может подставлять аргументы двумя способами: $ARGUMENTS — вся строка аргументов целиком; $1, $2, … — позиционные, где кавычки группируют слова в один аргумент:

Вызов$ARGUMENTSПозиционные
/review fix auth bugfix auth bug$1=«fix», $2=«auth», $3=«bug»
/review "fix auth" bugfix auth bug$1=«fix auth», $2=«bug» — кавычки сгруппировали
Плюс fallback: аргументы не теряются — если шаблон их не подставляет, они дописываются в body после пустой строки. Это разбирает интерактив «Собери команду» ниже.

Shell-блоки: данные до модели

Конструкция !`git diff` исполняет shell-команду и вставляет её вывод в промпт до отправки модели — удобно подложить контекст (диф, статус, список файлов), не копируя его руками.

⚠️ Warning из доков: shell-блоки выполняются вне permission-потока — разрешения не спрашиваются. Вставлять только доверенные команды; вся защита permissions из заметок 02 и 04 на этот механизм не распространяется.

subagent: true: команда в фоне

С этим флагом команда исполняется в фоновой child-сессии, а результат возвращается родителю — прямая параллель с субагентами из заметки 04: родитель заказал работу, исполнитель отчитался.

Приоритеты: источники и модель

  • Источники команд: проектные перекрывают глобальные, ближние перекрывают дальние — та же логика «ближний сильнее», что у слоёв конфигурации из заметки 03.
  • Модель: команда → агент → сессия. Самое специфичное побеждает: явный model в frontmatter перекрывает модель агента, а та — модель сессии.
  • Hot-reload: сохранение файла обновляет команду без рестарта — механика из заметки 03 распространяется и на команды.

Собери команду: живой предпросмотр /name

Настройте frontmatter, выберите пример вызова (пресеты — с кавычками-группировкой и без аргументов) и тело шаблона. · Хуки: перехватчики жизненного цикла


  
Хуки живут в плагинах

  
В V2 хук невозможно описать строкой конфига — он живёт в плагине. Плагин — это один npm-пакет (plugins overview), до четырёх частей:

  

    
Server
инструменты, хуки, интеграции, команды, агенты

    
TUI
терминальный интерфейс

    
GUI
desktop

    
RPC
типизированный контракт

  

  
SDK — один пакет @opencode/plugin; плагины автозагружаются из .opencode/plugins/. Заметьте: Server-часть плагина может привозить не только хуки, но и команды, и агентов.

Путь промпта с хуками: анимированный конвейер

    
Нажмите «Запуск» — «пилюля промпта» поедет по конвейеру. Каждая станция с цветным ярлыком домена — точка перехвата: карточка под схемой покажет, что хук видит и что может изменить. На трёх станциях (prompt, execute.before, create.before) хук правит демо-значение прямо на глазах: «до → после». После «Результата» каретка возвращается к модельному вызову — счётчик витков растёт. Механика перехватов — из заметки: домены, что хук видит / может изменить, финальность явного deny, ветка shell-инструмента, петля возврата с context-хуком на каждом витке. Демо-значения (тексты промпта, параметры npm test, пути) — иллюстративные. Несколько плагинов на одном хуке выполняются в порядке регистрации; изменения касаются только текущего вызова.

· Две философии: OpenCode V2 vs Claude Code

  
Аудитория доклада знает Claude Code — там тоже есть хуки, но философия другая (Claude Code hooks reference):

  

    
Claude CodeOpenCode V2

    
      
Что такое хуксобытие жизненного цикла: PreToolUse, PostToolUse, UserPromptSubmit, Stop, PermissionRequest, …TypeScript-API на типизированных доменах внутри плагина

      
Как настраиваетсяклассически — shell-команда в JSON-настройках; сейчас есть и другие типы обработчиков (HTTP-эндпоинты, MCP-вызовы, LLM-промпты, субагенты)код плагина (npm-пакет, SDK @opencode/plugin)

      
Философиядекларативный shell-обход: «на событие X запусти команду Y»программный API: типы, домены, композиция логики

    
  

  
Практическая разница: shell-команда легко пишется и так же легко разрастается в скрипты-«костыли»; плагин требует npm-окружения, зато даёт типизированный контракт и естественную эволюцию до инструментов и агентов.
