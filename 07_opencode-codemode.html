07. Code Mode в OpenCode V2: модель пишет программу, а не десятки вызовов

Обычный агентный цикл — лестница: вызвал инструмент → результат приехал в контекст → снова модель → следующий вызов. Пока задача не решена, каждый пролёт лестницы оставляет в контексте промежуточные значения, которые модели нужны были на секунду. V2 отвечает на это разворотом парадигмы: модель пишет маленькую программу, а сервер её исполняет — комбинация вызовов инструментов и обработка результатов происходят вне контекста модели, обратно возвращается только итог. Источники — раздел V2 tools docs, «Execute» и README пакета codemode.

· Мини-глоссарий

Code Mode
режим, в котором агент исполняет JavaScript-подобную программу через инструмент execute, чтобы вызывать и комбинировать инструменты каталога.
каталог инструментов
вся совокупность инструментов, доступных программе через неймспейсы.
снапшот каталога
стабильная фиксация каталога инструментов на каждый модельный запрос (server plugin docs).
песочница по построению
изоляция не надстройкой поверх языка, а отсутствием опасных возможностей в нём.
REPL-семантика
без явного return результатом становится значение последнего выражения верхнего уровня; undefined превращается в null.
неймспейс
именованная группа инструментов внутри Code Mode: opencode, browser, имя MCP-сервера.
Интерактив 1 · лестница vs программа

Одна задача — два режима работы агента

Задача: «проверь 5 файлов и сведи результат». Слева — обычный агентный цикл: лестница последовательных вызовов, каждый пролёт через модель. Справа — Code Mode: инструмент execute исполняет одну программу. Нажмите «Play» или идите по шагам — оба режима стартуют одновременно.

Фактология: без Code Mode каждый пролёт лестницы — отдельный модельный запрос, и промежуточные значения оседают в контексте, где устаревают. С Code Mode модель пишет одну программу, сервер её исполняет: параллельные независимые вызовы каталога инструментов + обработка результатов происходят вне контекста модели — промежуточные значения не попадают в контекст модели, обратно возвращается только итог. Числа файлов в демо — иллюстративные.

· Песочница по построению

Ключевое слово — «по построению»: программа не изолируется после запуска, она просто не имеет опасного. Рантайм Code Mode — без прямого доступа к файловой системе, без imports и без таймеров; из внешнего мира есть только fetch; всё остальное — через каталог инструментов.

песочница по построению = изоляция не надстройкой поверх языка, а отсутствием опасных возможностей в нёмножницы безопасности срабатывают одним правилом

Ножницы безопасности срабатывают одним правилом: запрет execute с resource * удаляет Code Mode и все инструменты, достижимые только через него (механика permissions — из заметки 04). Что при этом исчезает — смотрите на карте ниже.

· Не произвольный JS: интерпретатор подмножества

Code Mode — не «запусти любой JavaScript», а «исполни только то, что реализовано». README описывает рантайм как lightweight, pure interpreter for a JavaScript-like language — программы не могут напрямую трогать сеть, файловую систему, процессы и API приложения. Отличия от обычного JS — в таблице:

Обычный JSCode Mode
вся экосистема: imports, npm-пакетытолько поддерживаемые API; imports нет
незавершённые async-операции живут, пока жив рантаймнедождавшиеся async-операции прерываются при завершении программы
результат — куда положишь (side effects, console)REPL-семантика: без явного return — значение последнего выражения верхнего уровня; undefined → null
любой синтаксис валиден для парсеранеподдерживаемый синтаксис → диагностика UnsupportedSyntax

Идея не придумана OpenCode: подход code mode предложила Cloudflare как изолят-подход к агентам (Cloudflare code mode post); OpenCode реализовала собственный интерпретатор.

· Лимиты и аудит

Программа — ресурс ограниченный и просматриваемый:

  • timeoutMs — время;
  • maxToolCalls — число вызовов инструментов;
  • maxOutputBytes — размер вывода.

Аудит встроен: toolCalls хранит полный лог допущенных вызовов, а search(...) ищет по каталогу инструментов прямо из программы.

· Неймспейсы внутри Code Mode

Внутри программы инструменты сгруппированы по неймспейсам:

opencode

· Снапшот каталога и runtime-хуки

Две гарантии предсказуемости. Первый: каждый модельный запрос фиксирует стабильный снапшот каталога инструментов — программа видит одну и ту же картину на протяжении запроса. Второй: каждый вызов программы в хост окружают runtime-хуки Code Mode.

runtime-хуки Code Mode
tool.before / tool.after
Опция hooks в CodeMode.make. Окружают каждый вызов программы в хост: перехват живёт на стороне рантайма Code Mode.
plugin API — не путать!
ctx.tool: execute.before / execute.after
Родственный per-call перехват в plugin API живёт на домене ctx.tool с именами execute.before / execute.after — именно он разобран в заметке 05.
Разведение: runtime-хуки Code Mode (tool.before/tool.after, опция hooks в CodeMode.make) и plugin-хуки домена ctx.tool (execute.before/execute.after) — разные API; общая у них идея — аудит каждого вызова.

· Две формы делегирования: программа и субагент

Code Mode и субагенты отвечают на разные вопросы, и это две ортогональные оси:

Code Mode (execute)субагенты (заметка 04)
Сутькомпозиция инструментов внутри одной программыотдельные сессии со своими ролями и правами
Контекстпромежуточные значения не попадают к моделиу субагента свой контекст: получил бриф — вернул отчёт
Сильная сторонапараллельные независимые вызовы, механическая обработка результатовсодержательная специализация: исследование, написание, ревью

Правило большого пальца: работу механическую — «сходи туда, туда и туда, посчитай» — отдавайте программе; работу смысловую — требующую своей модели и своего промпта — субагенту.

· Живой пример: этот доклад готовится самим V2

Врезка без выдумки: материалы этого цикла создаются мультиагентским конвейером на OpenCode V2 — оркестратор Newton раздаёт брифы субагентам (заметка 04), а вызовы инструментов оркестратора идут через Code Mode. Доклад про V2 готовится самим V2.
