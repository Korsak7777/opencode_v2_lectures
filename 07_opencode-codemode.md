# 07. Code Mode в OpenCode V2: модель пишет программу, а не десятки вызовов

Обычный агентный цикл — лестница: вызвал инструмент → результат приехал в контекст → снова модель → следующий вызов. Пока задача не решена, каждый пролёт лестницы оставляет в контексте промежуточные значения, которые модели нужны были на секунду. V2 отвечает на это разворотом парадигмы: **модель пишет маленькую программу, а сервер её исполняет** — комбинация вызовов инструментов и обработка результатов происходят вне контекста модели, обратно возвращается только итог. Источники — раздел [V2 tools docs, "Execute"](https://opencode.ai/v2/docs/tools) и [codemode README](https://github.com/anomalyco/opencode/blob/dev/packages/codemode/README.md).

```text
БЕЗ CODE MODE: лестница вызовов - каждый пролёт через модель

   модель -> вызов инструмента -> результат В КОНТЕКСТ -> модель ->
   -> вызов инструмента -> результат В КОНТЕКСТ -> модель -> ...
   (N вызовов = N модельных запросов; промежуточные значения
    оседают в контексте и там же устаревают)

С CODE MODE: одна программа вместо лестницы

   модель -> [ execute: маленькая программа ]
                    |
                    |  комбинации вызовов каталога инструментов
                    |  (параллельные независимые + обработка результатов)
                    v
   модель <- только итог (промежуточные значения остались
              внутри программы, в контекст не попали)
```

## Мини-глоссарий

- **Code Mode** — режим, в котором агент исполняет JavaScript-подобную программу через инструмент `execute`, чтобы вызывать и комбинировать инструменты каталога.
- **каталог инструментов** — вся совокупность инструментов, доступных программе через неймспейсы.
- **снапшот каталога** — стабильная фиксация каталога инструментов на каждый модельный запрос ([server plugin docs](https://opencode.ai/v2/docs/build/plugins/server)).
- **песочница по построению (sandbox by construction)** — изоляция не надстройкой поверх языка, а отсутствием опасных возможностей в нём.
- **REPL-семантика** — без явного `return` результатом становится значение последнего выражения верхнего уровня; `undefined` превращается в `null`.
- **неймспейс** — именованная группа инструментов внутри Code Mode: `opencode`, `browser`, имя MCP-сервера.

## Песочница по построению

Ключевое слово — «по построению»: программа не изолируется после запуска, она просто не имеет опасного. Рантайм Code Mode — без прямого доступа к файловой системе, без imports и без таймеров; из внешнего мира есть только `fetch`; всё остальное — через каталог инструментов. Ножницы безопасности срабатывают одним правилом: запрет `execute` с resource `*` удаляет Code Mode **и все инструменты, достижимые только через него** (механика permissions — из [заметки 04](04_opencode-multiagent.md)).

## Не произвольный JS: интерпретатор подмножества

Code Mode — не «запусти любой JavaScript», а «исполни только то, что реализовано». README описывает рантайм как lightweight, pure interpreter for a JavaScript-like language — программы не могут напрямую трогать сеть, файловую систему, процессы и API приложения. Отличия от обычного JS — в таблице:

| Обычный JS | Code Mode |
|---|---|
| вся экосистема: imports, npm-пакеты | только поддерживаемые API; imports нет |
| незавершённые async-операции живут, пока жив рантайм | недождавшиеся async-операции прерываются при завершении программы |
| результат — куда положишь (side effects, console) | REPL-семантика: без явного `return` — значение последнего выражения верхнего уровня; `undefined` → `null` |
| любой синтаксис валиден для парсера | неподдерживаемый синтаксис → диагностика `UnsupportedSyntax` |

Идея не придумана OpenCode: подход code mode предложила Cloudflare как изолят-подход к агентам ([Cloudflare code mode post](https://blog.cloudflare.com/code-mode/)); OpenCode реализовала собственный интерпретатор.

## Лимиты и аудит

Программа — ресурс ограниченный и просматриваемый: `timeoutMs` (время), `maxToolCalls` (число вызовов инструментов), `maxOutputBytes` (размер вывода). Аудит встроен: `toolCalls` хранит полный лог допущенных вызовов, а `search(...)` ищет по каталогу инструментов прямо из программы.

## Неймспейсы внутри Code Mode

Внутри программы инструменты сгруппированы по неймспейсам:

- **`opencode`** — служебные инструменты самого OpenCode: `session_rename`, `session_move`, `worktree_*` — именно отсюда инструменты [заметки 06](06_opencode-worktree.md);
- **`browser`** — управление браузером desktop-приложения;
- **MCP-серверы** — их инструменты по умолчанию доступны агенту через `execute` под неймспейсом своего сервера; настройка `codemode: false` выводит их наружу прямыми инструментами ([MCP servers docs](https://opencode.ai/v2/docs/mcp-servers)).

## Снапшот каталога и runtime-хуки

Две гарантии предсказуемости. Первый: каждый модельный запрос фиксирует **стабильный снапшот каталога инструментов** — программа видит одну и ту же картину на протяжении запроса. Второй: каждый вызов программы в хост окружают runtime-хуки Code Mode — `tool.before` / `tool.after` (опция `hooks` в `CodeMode.make`). Не путать с плагинами: родственный per-call перехват в plugin API живёт на домене `ctx.tool` с именами `execute.before` / `execute.after` — именно он разобран в [заметке 05](05_opencode-commands-hooks.md).

## Две формы делегирования: программа и субагент

Code Mode и субагенты отвечают на разные вопросы, и это две ортогональные оси:

| | Code Mode (`execute`) | субагенты ([заметка 04](04_opencode-multiagent.md)) |
|---|---|---|
| Суть | композиция инструментов внутри одной программы | отдельные сессии со своими ролями и правами |
| Контекст | промежуточные значения не попадают к модели | у субагента свой контекст: получил бриф — вернул отчёт |
| Сильная сторона | параллельные независимые вызовы, механическая обработка результатов | содержательная специализация: исследование, написание, ревью |

Правило большого пальца: работу **механическую** — «сходи туда, туда и туда, посчитай» — отдавайте программе; работу **смысловую** — требующую своей модели и своего промпта — субагенту.

## Code Mode одним взглядом

| Вопрос | Ответ |
|---|---|
| Что это | инструмент `execute`: модель пишет JavaScript-подобную программу вместо десятков вызовов |
| Зачем | параллельные независимые вызовы; промежуточные значения не попадают в контекст |
| Песочница | по построению: без FS, imports, таймеров; извне — только `fetch`; всё через каталог |
| Выключение | запрет `execute` с resource `*` удаляет Code Mode и всё, достижимое только через него |
| Язык | интерпретатор подмножества JS: только поддерживаемые API; `UnsupportedSyntax` на остальное |
| Отличия от JS | async прерывается при завершении; REPL-результат (`undefined`→`null`) |
| Лимиты и аудит | `timeoutMs`, `maxToolCalls`, `maxOutputBytes`; лог `toolCalls`; `search(...)` |
| Неймспейсы | `opencode` (`session_move`, `worktree_*`), `browser`, MCP-серверы (`codemode: false` — наружу) |
| Стабильность | снапшот каталога на каждый запрос; runtime-хуки `tool.before`/`tool.after` вокруг каждого вызова программы |
| Родословная | code mode — Cloudflare (изолят-подход); интерпретатор — собственный OpenCode |
| vs субагенты | механическая композиция инструментов ↔ смысловая специализация в отдельных сессиях |
